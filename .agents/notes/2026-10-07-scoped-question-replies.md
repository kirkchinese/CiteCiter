# Bind late question replies to the Topic contribution scope

Date: 2026-10-07. Scope: official Desktop 0.2.0-rc.2 and Web SDK 0.2.1-alpha.1, CiteCiter 0.9.0-alpha.4 candidate.

Real GPT-6-Sol acceptance reproduced a late-reply failure. A timed ask_user_question continued after 5,038 ms, the Topic was archived and reopened, and its continued question remained visible. Submitting the answer displayed `cannot get property "userQuestions" without inject`. No user-question-reply or new model turn was recorded, and archive state remained unchanged. The first blocking question worked because the official tool plugin explicitly injects userQuestions; Citer's separate late-answer RPC incorrectly read that service directly from the Agent's base context.

TopicQuestionReplies now registers a child plugin with an explicit userQuestions dependency in each Topic contribution scope. It routes answers to the exact live Agent through the official service's answer method. A WeakMap stores the bound operation; scoped cleanup removes only the matching binding when the service unloads or the Topic is disposed. Both hosted and legacy Topic setup use this boundary. Missing service state returns an explicit error without recreating the Agent or bypassing official caller validation. The Host Agent Loop, source Session services, permissions and durable event formats are unchanged.

Both SDK Host/Client type checks and git diff --check passed. An inline check with the real Cordis and UserQuestionService reproduced the old injection error, confirmed that the replacement reaches the official CALLER_NOT_LIVE validation, and checked service unload, reload and Topic-scope disposal. It did not use a substitute model or retain a test script. The corrected package was built and installed as candidate 13ce8465119a; all 151 installed files match its archive. Native late-answer and archive-restoration verification is recorded separately in the official acceptance report.

The installed candidate subsequently accepted the real late reply in Topic 2: its question card disappeared and the model answered with the requested bookmark-button example. This exposed a second display defect. topicMessages admitted only ordinary user sources; contextMessage classified the official user-question-reply as injected context, which the Client hid. The reply was durable at sequence 32, but the transcript showed adjacent assistant responses without the user's intervening choice. Both official SDKs include a dedicated question-reply chat projection, so this is an omitted compatibility projection rather than a new product behavior.

The new pure question-reply module validates the recorded payload and matches its callId and question/answer identities. It has no Host or Client service imports. Topic messages now project committed late replies before generic context handling, retaining their original message ID and sequence. A small Client component presents the question, selected option labels, free text and an explicit skipped state as plain React text. It does not render model-facing JSON or internal metadata as the user's message. Damaged, mismatched or incomplete records show an unreadable-history notice without exposing their raw payload. Existing ordinary user messages and injected contexts keep their prior behavior.

The matching ask_user_question tool row receives a derived answered summary linked by callId. Its original result, including pending:true when the tool timed out, remains unchanged: that result records what happened at the time, while the later user message records the answer. This does not rewrite the log, fabricate a new answer, alter source Sessions, import an internal upstream UI module or change the official answer service. Existing cancellation and interruption outcomes remain available as recorded.

The pure reader was checked inline against the actual Topic 2 sequence 32: the question was “解释 UI 状态同步更新时，你希望哪种方式？” and the selected answer was “给出小例子”; the derived summary is “已补答 · 给出小例子”. Additional boundary checks covered reordered answer IDs, multiple choices plus free text, preserved Chinese/English/code characters and newlines, explicit skip, duplicate or missing answers, mismatched callId and malformed JSON. Both SDK Host/Client type checks and git diff --check passed after this display change. No test script, test model or fixture file was retained. These parser and static checks are separate from the installed-package UI observations below.

Candidate 12969b783645 was built, installed and restarted in the official Desktop. Historical selected-option and custom-text late answers appeared as user bubbles, with their associated tool rows showing derived answered summaries. A new real 12-second timed question contained two items; the user answered Python to the first and skipped the second after the question continued. The transcript displayed both questions, Python and an explicit “已跳过”; the tool summary displayed “已补答 · Python、已跳过”, and the real model correctly restated the selection and skip. The original timed-tool result remained a historical record rather than being rewritten.

Independent review identified that trimming custom text before presentation could remove meaningful leading code indentation and trailing whitespace from a submitted answer. The reader now uses trim only to decide whether custom text is blank, while retaining the original string for display and plain-text consumers. An inline parser check verified exact preservation of leading/trailing spaces, tabs and newlines with mixed Chinese, English and code, retained selected-option order, and unchanged skip behavior for whitespace-only text. Both SDK Host/Client type checks passed again. This correction changes presentation only; no log or submission behavior changed.

The whitespace-preserving revision was then built and installed as candidate 255f5aa1f764. All 153 installed files matched the packed archive. After a real official-Desktop restart, native window 1441826 showed the same correct historical late-answer bubbles and derived tool summaries. This confirms installed-package restart presentation for the recorded replies; exact edge-whitespace preservation is additionally covered by the parser check, not claimed as a newly entered native-IME test. The full acceptance matrix remains incomplete. These scoped successes do not authorize a release or automatically transfer other candidates' functional evidence to the current package; the official acceptance report remains the source of the complete status.
