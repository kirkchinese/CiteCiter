# Official Desktop and Git repository installation

Date: 2026-10-07. Candidate: CiteCiter 0.9.0-alpha.4. This work changes the supported Desktop target to the official DeepSeek Harness application. It does not publish a release or establish complete functional acceptance.

## Ownership and removal decision

The user explicitly withdrew community Desktop support and requested removal of its repository content and acceptance evidence. This overrides the normal freeze on archived Agent Notes for that material. Community-only startup code and notes are removed; mixed documents retain only their independent Web observations, general engineering decisions and release facts. Community Desktop observations are not evidence for the official application. Git history is preserved, and source sessions, Citer-owned logs, migration backups and original video material are not deletion targets.

The installed community application was uninstalled. The official signed Windows installer reports 0.2.0-rc.2 and installs at the vendor's DeepSeek Harness path. The main DSH home remains in place. The obsolete community desktop-shell profile entry was removed after backing up profile configuration. A later read-only audit covered 80 ignored cleanup targets and retained the isolated browser-state directory separately; the other 79 were within the workspace, without active process references, and their internal links remained within the temporary audit tree. Automatic approval still rejected the bounded PowerShell deletion with only `blocked by policy`; none of those targets was removed and no other tool was used to bypass the rejection.

## Engineering decisions

The canonical package remains in packages/citeciter. The repository root now declares a real Git-installable plugin using the same committed lib files, exports and bundle patch. A synchronization/check command derives root metadata from the canonical package. Root build commands use explicit directory selection to avoid recursively running both identically named workspace packages. Git installation requires no prepare hook, nested file dependency or redirect to a previously published npm version. npm packing still targets the canonical inner package.

The primary SDK is 0.2.1-alpha.1; the separately pinned official Desktop SDK gate is 0.2.0-rc.2. Obsolete settings, icon, preview and Typert fallbacks were removed while keeping those boundaries modular. Runtime modules resolve from the actual official app/dsh or app.asar/dsh installation; CLI entry points still resolve symlinks. Update commands use the public profileContext name, without a community-only service.

Layout measures the official content row, preserving Windows chrome, native details and alpha's bottom slot. Topic questions follow the official dismiss, foreground wait and late-answer contracts while remaining outside the Host Session list. A real user late reply restores an archived Topic just as another manual send does. See the separate question-adapter note for lifecycle decisions and limits. No Host Agent Loop or persisted DSH log format was rewritten.

Real official-Desktop acceptance exposed a cancelled question displayed as a failed call. The repair preserves only the official structured cancellation/interruption codes through a pure shared outcome contract, without importing Host Context declarations into the Client graph or changing original log events. The new candidate restores the observed cancelled history row as “已取消”; a separate real stop action closes the question form, shows “已中断” and leaves a resumable stopped turn without retries. See [the outcome note](2026-10-07-question-tool-outcome.md) for the implementation and type-boundary evidence.

A subsequent rejected write exposed a separate presentation problem. The new isolated `tool-approval-projection.ts` derives a rejected summary only from an unambiguous ordered call → approval request → rejected decision → failed result chain. Missing identities, duplicate or ambiguous events, unknown outcomes and successful results produce no rejection verdict; PTC child calls retain their own IDs. Permission enforcement, original tool results and persisted events are unchanged. Both SDK typecheck gates, pnpm build and git diff --check passed for this source change. The original `255f5aa1f764` candidate predates it; the repair has since been installed and verified in the native UI on `636409058e77`, as recorded below.

The build also had an intermittent Windows truncation failure: reopening the emitted client bundle in postbuild produced Windows error 1224 when its region was mapped. Normalization now occurs in `generateBundle` before the first file write; the redundant postbuild rewrite is removed. Twenty consecutive bundles, the root build and package pack succeeded, with the same six JavaScript hashes as the old successful normalization. There are no sleep/retry workarounds or ignored errors, and the mapping owner was not identified. See [the build lifecycle note](2026-10-07-bundle-write-lifecycle.md).
