# 0.8.0 消息附件与发布

用户确认 source-world-32 的跨窗口拖放行为正确，要求移除用户消息的“你”标签、将纸夹表情替换为可点击附件控件，并发布 0.8.0 正式版。发布授权覆盖 npm latest 与对应 GitHub Release；不推断为合并开发分支的授权。

用户消息保留内容气泡和无障碍标签。MessageFile 使用宿主下载图标、文件名、键盘按钮语义和错误重试状态。file-download 独立管理按需请求、重复点击、Topic 切换后的晚到结果和对象 URL 清理，不访问 Cordis 服务，也不触发模型。

第一轮真实 Desktop 下载暴露既有读取接口的限制：SessionFace.readAttachment 的已安装类型虽然使用附件命名，实际仅返回 ImageAttachmentRef。Citer 原先的 native-image 授权扫描也只遍历图片块，导致历史中存在的普通日志文件被拒绝为“此图片未被当前 Citer 会话引用”。用户实际点击提供了明确失败回执，不能把此前类型检查通过作为功能正确的证据。

读取现已统一为 native-attachment。新的 native-attachment-read 模块从确切 Topic 的持久消息与工具结果查找图片或文件引用，使用 DSH readImage 或 readFileStream 读取；普通文件的原生完整性校验保持有效。客户端 readCiterAttachment 承担通用接口；实现 SessionFace 时仍尊重其图片专用类型，不伪造图片宽高或 MIME。文件下载使用 application/octet-stream，图片仍按原生媒体类型预览，不用扩展名猜测类型。

0.8.0 安装包已安装到主要 Web 与 Desktop，原生截图确认用户标签消失且已有真实图片继续显示。文件下载回归中 Computer Use 出现桌面合成错误及 GPU device removed，按重选流程重试仍失败，后续点击由用户完成。用户确认修复后下载成功，并再次要求发布。最终观察与验收边界见 docs/validation/2026-09-12-native-real-model.md。未创建模型替身或临时测试脚本。
