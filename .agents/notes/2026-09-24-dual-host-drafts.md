# Dual-host candidate and durable drafts

Status: implemented, static gates passed, functional acceptance incomplete. No publication is authorized by this plan.

## Final boundaries

One 0.9.0-alpha.1 package targets Web SDK 0.1.7-rc.2 and Desktop 2.0.13's SDK 0.1.5-rc.2 through settings, Typert, message, interaction and icon adapters. The private citeciter-compat-desktop workspace pins the installed Desktop SDK; check-desktop.mjs compiles the same Host and Client sources without changing production resolution. No host Agent Loop is patched. The resources/app and app.asar launcher fix is now part of normal source and build, replacing the earlier stable backport described in 2026-09-24-rc-desktop-packaging.md.

Citer owns each source's citeciter subtree. Session format guards refuse old-host writes when a newer native successor log exists, including source discovery and owned Topic loading. Format migration remains with DSH. Rejection is explicit; no v4-to-v3 rewrite or lossy fallback is attempted.

Draft state is a separate contract, storage service and client controller. Text, actual references and file bytes reside under the owning Topic's draft directory. The controller outlives React panel mounting, re-registers restored files with the native attachment API and compares revision numbers before saving. Unsent drafts never enter model logs or authorize source reads. Admission stores the exact outgoing snapshot and a durable request identity; host acknowledgment clears only that snapshot, preserving later edits. Lost responses remain pending, and retry requires a user action. Receipt reconciliation does not replace in-flight edits. Navigation warns while local changes remain unsaved. Permanent Topic deletion includes the verified draft subtree.

## Limits

Real Web acceptance on candidate 79a436fc5e88 reproduced a submission race: Enter followed immediately by editing sent the later draft instead of the clicked question. submit() captured content after awaiting flush(). It now captures the immutable content and pins attachments through pending before the first persistence await. Candidate 3441c3ba77a3 was installed through the main Web CLI; the identical UI sequence logged only the original Promise.allSettled question (user/message seq 33), while revision 11 retained the later draft with pending=null. A real answer completed. No model provider was simulated.

The Web 79a436fc5e88 run also observed both native queue and Ctrl+Enter steering, correct processing order, closed-panel blackboard_view (1000×680, 240,061 bytes), two real attachments surviving page and host restarts, and two-window CAS conflicts with both explicit resolutions. A repeated Topic creation reached its new title in 617 ms. These observations remain candidate-specific.

Windows prepack intermittently failed with TS5033 UNKNOWN at varying lib/types files. A subsequent full pack passed without permission changes. This narrows the issue to intermittent file I/O but does not identify the occupying process or establish a permanent build fix.
