# Agent Note: 0.4.1 阻断项修复

状态：已实现

## 问题

0.4.0 发布后审计发现两个 P1 和两个 P2：后续回答可能显示机器控制标记，单个超大来源事件会卡住分页，重复快捷提问或创建点击可能并发，设置页配置文件操作没有可见结果。

## 决策

对每条助手回答执行控制标记解析，但只从第一条助手回答生成快捷问题。这样实时、完成、迟到和重放都走同一正文隐藏路径。

当单个事件连空页预算都放不下时，返回紧凑的 `{type, seq, oversized}` 记录。普通事件在页边界前停止，调用方下一次仍可读取该事件；这既保证进度，又不把无界模型证据返回给模型。

对完整 Client 意图计算 `sessionStorage` 键，只在 Host 确认前保留重试稳定的请求 ID。创建按请求 ID 执行 single-flight 并拒绝载荷不一致的复用；追问按 Topic 执行 single-flight，因此切换 Topic 不会抑制有效问题，Host 也会串行接纳同一 Topic 的提问。Host 在扫描索引前登记创建任务，修复已经提交但缺少首问的 Topic，并把创建与追问请求 ID 用作持久用户消息 ID。重试查找会重建尚在排队的 inbox splice；Host 重启后，重试会取消并用同一 ID 重新排入排队消息，而在领取后、提交前的窗口里查不到排队或已提交副本时，重试会用请求携带的同一 ID 和问题重新入队。在线 Agent 一旦领取问题，调用方取消只会停止该调用方的等待；同 ID 重试会复用 Host 持有的持久化 promise，直到消息提交、被丢弃、所属 turn 结束或运行时关闭。Host 只在该 ID 已持久写为 `user/message` 后确认操作；之后相同的用户操作则取得新的请求 ID。

配置文件按钮使用共享 Settings describe 镜像和 Host `settings.openDocument` 操作，不接收任意 Host 文件系统路径。CiteCiter 设置页现在显示不可用、打开中、成功和可恢复失败状态。

## 备选方案

只解析第一条回答会在后续控制块出现时重新泄漏。

返回完整超大事件会破坏现有的 128 KiB 模型可见页上限。

在浏览器中直接打开本机路径会绕过 Host 路径权限和 loopback 防护。

每次重试生成新的随机请求 ID 会在响应丢失后创建重复 Topic。

只在 Host 内存中保存成功追问 ID 虽能覆盖浏览器刷新，却不能覆盖 Host 重启，并且会随进程运行持续增长。

## 影响

Client 声明 `@deepseek-ai/dsh-client-connection`，`.dsh.client.inject` 包含 `connection`。确定性夹具把首轮控制标签拆到多个流式分块，检查后续完成回答与刷新重放都不泄漏控制文本，双击创建时断言只有一个 Topic，双击快捷问题时断言只有一条用户消息。Exact 来源读取先按分叉序列过滤来源快照再分页，Observer 则继续读取后续已提交事件。既有 Topic 元数据和 Session 事件格式仍然有效。包含 Desktop 覆盖抽屉与生命周期修复后，Client bundle 从 424,719 增长到 442,287 bytes（4.14%），低于 5% 发布门禁。
