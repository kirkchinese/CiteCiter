# Agent Note: 0.4.1 blocking fixes

Status: implemented

## Problem

The 0.4.0 post-release audit found two P1 and two P2 behaviors: machine control markup could appear after a later answer, one oversized source event could stop pagination, repeated shortcut or creation clicks could race, and the settings configuration action had no observable result.

## Decision

Apply control parsing to every assistant answer and render shortcuts only from the first assistant answer. This keeps real-time, completed, late, and replay projections on the same hidden-body path.

Represent a source event that cannot fit even an empty page as a compact `{type, seq, oversized}` record. Stop an ordinary event at the page boundary so the caller can request that same event next; this preserves progress without returning unbounded model evidence.

Hash the complete Client intent to a `sessionStorage` key and retain a retry-stable request ID only until the Host confirms that intent. Concurrent creation is single-flight by request ID and rejects mismatched reuse; follow-up submission is single-flight per Topic so changing Topics cannot suppress a valid question, and the Host serializes admission within each Topic. The Host reserves creation before scanning its index, repairs a committed Topic that lacks its first question, and uses creation and follow-up request IDs as durable user-message IDs. Retry lookup reconstructs pending inbox splices; after a Host restart, a retry cancels and re-enqueues queued work, while a lookup that finds neither a queued nor committed copy in the claimed-before-commit window re-enqueues the request's same ID and question. Once the live Agent claims a question, caller cancellation stops only that caller's waiter; retries join the Host-owned durability promise until the message commits, is discarded, its turn ends, or the runtime shuts down. The Host acknowledges an operation only after that ID is durable as a `user/message`. A later identical user action receives a new request ID.

Use the shared Settings describe mirror plus the Host `settings.openDocument` operation. The CiteCiter settings page now reports unavailable, opening, success, and recoverable failure states without receiving an arbitrary Host filesystem path.

## Alternatives considered

Parsing only the first answer would leave a later control block visible.

Returning the full oversized event would violate the existing 128 KiB model-visible page bound.

Opening a locally resolved path from the browser would bypass the Host path authority and loopback fence.

Generating a new random request ID for each retry would allow response loss to create a second Topic.

Keeping successful follow-up IDs only in Host memory would deduplicate browser refreshes but not Host restarts and would grow for the process lifetime.

## Consequences

The Client declares `@deepseek-ai/dsh-client-connection`, and `.dsh.client.inject` includes `connection`. The deterministic fixture splits the first control tag across stream chunks, checks the completed later answer and replay for leaked control text, double-submits creation while asserting one Topic, and double-submits a shortcut while asserting one user message. Exact source reads filter their source snapshot at the fork sequence before pagination, while Observer reads continue to see later committed events. Existing Topic metadata and Session event formats remain valid. With the Desktop overlay and lifecycle fixes included, the Client bundle grows from 424,719 to 442,287 bytes (4.14%), below the 5% release gate.
