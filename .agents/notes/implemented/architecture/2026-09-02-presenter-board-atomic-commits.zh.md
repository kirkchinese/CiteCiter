# Agent Note: Presenter 黑板原子提交

Status: implemented

## Problem

Presenter 最初同时接受助手正文控制块和 `blackboard_apply` 调用，并在结果确认执行是否成功前投影调用。两个通道为同一次黑板更新提供了相互竞争的提交含义，会让协议标记进入回答流，也允许被拒绝的工具调用改变回放画面。每次 Topic 快照发送全部历史操作还会使轮询成本随 Topic 历史持续增长。

## Decision

协议 v4 只有一个提交事实：`blackboard_apply` 的 `tool/call` 必须按 `callId` 配对成功的 `tool/result`。失败、取消、中断和未配对调用不改变黑板。投影器在临时 Map 上应用每个成功批次；只有全部操作和完整结果都满足协议限制时，才发布新状态。

`blackboard_apply` 通过 rc.2 `defineTool` schema DSL 向模型暴露完整操作联合。执行器继续校验模型可见 DSL 无法表达的正则、数值范围、跨字段关系、内容类型、目标存在性和完整结果预算。有状态操作拒绝未知目标，`remove` 保持幂等。工具定义没有选择并发调度，因此调用排他执行。

`BoardSnapshot` 包含最终有序元素、成功提交 revision 和非法成功记录计数，不包含操作历史或助手流式操作。持久 Session 仍是权威来源；插件不扩展 `SessionEventMap`。

内置场景提示词始终位于可选用户教学偏好之前，并在偏好之后追加不变式提醒。偏好可以改变教学风格，但不能替换只读行为、证据处理、工具策略或黑板协议。

## Alternatives considered

**保留助手控制块作为低延迟通道。** 部分正文没有工具执行结果，无法共享原子提交规则；控制块还会让回答格式依赖协议解析，并把畸形或尾随标记变成用户可见问题，因此放弃。

**立即投影每个 `tool/call`。** 调用只是请求。DSH 在 `tool/result` 中记录规范化的成功或失败；只使用请求会违背工具管线的提交点，因此放弃。

**增加黑板专用 Session 事件。** 现有调用/结果对已经记录全部模型可见输入与结果；第二份持久事实可能与工具日志不一致，并要求所有 Session 读取器理解新的 required 事件，因此放弃。

**在每个快照中保留操作历史。** 回放属于 Host，轮询消费者只需要当前渲染状态；最终状态快照使传输和客户端折叠受黑板预算约束，而不随 Topic 长度增长，因此放弃。

## Consequences

黑板只在工具结果提交后改变，不会在模型流式输出时渲染部分 JSON。标准 Agent step 仍支持增量教学：模型可以提交小批板书、讲解，再提交后续更新。

浏览器 bundle 内联 KaTeX CSS 和 woff2 字体，因此数学板书无需公开资源路由或外部字体请求也能保持正确排版。

预发布 v1-v3 黑板控制块与操作历史快照不是兼容输入。现有 Topic 日志保持不变，但 v4 不把其中的助手标记解释为黑板状态。

最终黑板最多 50 个元素和 500,000 UTF-8 内容字节，单次提交最多 50 个操作。这些是协议与资源安全限制，不是部署调优参数。
