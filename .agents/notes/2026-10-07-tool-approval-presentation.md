# Preserve explicit tool-approval rejection in the transcript

Date: 2026-10-07. Scope: presentation on the official DSH Desktop 0.2.0-rc.2 baseline and Web SDK 0.2.1-alpha.1. Community desktop records are not compatibility evidence.

Real acceptance on installed candidate `255f5aa1f764` exposed a misleading summary: the user rejected the native `write` approval, the tool stayed denied and the model stopped, but Citer displayed “调用失败”. In acceptance source `session-34316b58-111a-4f71-a2db-3922e57d7446`, Topic 4, `tool/call` seq 36 was followed by `approval/asked` seq 37 with the same call ID. `approval/decided` seq 38 recorded `rejected` at 13:56:31.329 +08:00, and seq 39 returned `isError: true` one millisecond later. The official sandbox escalation path throws a plain Error for this decision, so its tool result has no structured error code. The model explained the rejection at seq 43 and ended the turn at seq 46; no tool call followed the rejection, the target file did not exist, and the Topic remained read-only.

The new Host-only `tool-approval-projection.ts` reads the public approval audit events without service discovery, permission changes or error-text matching. It requires one exact call, one matching ask, one explicit rejected decision and one failed result, in sequence order. Approval identity, exact call identity and tool name must agree. Missing IDs, reused IDs, duplicate calls or results, multiple approvals, unknown decisions, wrong tool names, out-of-order events and successful results yield no special verdict. PTC children use their own dispatch IDs; their containing `run_code` result never inherits the child's verdict. Incomplete or ambiguous historical data retains the ordinary summary.

`topicMessages()` applies this projection to the private Topic's post-seed events for both current snapshots and restored history. Its optional `approvalOutcome: 'rejected'` field is presentation evidence, distinct from the question-error taxonomy. `ToolMessage.tsx` displays “已拒绝” and a neutral “状态” detail heading only on a completed error row carrying that field. Original error text, result content, `isError`, Session events, source logs, Agent Loop and approval behavior are unchanged. Shared `topic.ts` adds only a finite optional schema field; it does not import the Host projection into the Client type graph.
