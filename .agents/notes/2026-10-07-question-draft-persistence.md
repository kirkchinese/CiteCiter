# Question-card draft persistence

The user confirmed that unsubmitted model question answers must persist and restore like the main composer, without automatic submission. The previous installed Git candidate `f0c30dd` lost question-card input across a complete official Desktop exit/restart; its ordinary composer drafts remained intact. This change implements that confirmed behavior without changing the Host Agent Loop, source Session logs, model settings or permission defaults.

## Boundaries

`question-draft-contract.ts` validates versioned content: partial selections, unmodified custom text, page, and explicit edited/held intent. `question-draft-store.ts` stores one key-bound, revision-checked record under the owned Topic's `question-drafts/`, with atomic replacement and link checks. It accepts incomplete answers, detects concurrent edits, and retains closed empty records so late saves cannot resurrect submitted answers. Permanent Topic cleanup removes these owned records.

`question-draft-lifecycle.ts` recognizes the exact post-seed ask call and its actual user-question-reply admission or terminal tool result. Queued replies, pending results, timeout and unknown-outcome repair are not proof of acceptance. Closed is monotonic for the call. The Topic runtime reconciles committed receipts on reopen and serializes saves/cleanup with its existing admission queue; synchronous Host event handlers never await that queue.

The independent Client draft controller echoes edits synchronously and saves in the background. React does not await storage to update controlled inputs and shows no saving indicator. Recovery gates editing until the initial read finishes; errors and CAS conflicts preserve local text and expose explicit recovery actions. Selected options, code indentation, custom text and the current question page survive restoration. Restoring edited/held intent cannot restart a countdown on blur. Restoration never calls the answer channel. Successful answer RPC delivery alone does not clear durable state because late answers may still be queued.

Question carriers outlive their React cards. Visibility changes and unload guards flush their drafts along with ordinary composer drafts; disposal flushes without submission. Exact authoritative Topic deletion retires all owned carriers and attachments. Durable minimal deletion receipts are documented separately; generic network errors or an absent list row do not imply deletion. Normal Topic reads do not scan all deletion receipts; that lookup is reserved for absent metadata. Reads and draft operations are serialized with deletion.
