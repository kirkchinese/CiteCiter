# CiteCiter 最新宿主验收

候选版本 `0.7.0-beta.2`，未发布 npm。用户在旧基线验收期间要求“换成最新版”，最终目标改为 DSH npm latest `0.1.5-rc.1` 与社区 Desktop `2.0.9`。环境为 Windows、Node `24.19.0`、pnpm `11.21.0`。旧阶段结果见 [9 月 10 日记录](2026-09-10.md)。

## 版本和安装

Desktop 安装包来自 [2.0.9 发布页](https://github.com/anywhere-labs/dsh-desktop/releases/tag/v2.0.9) 提供的镜像，SHA-256 为 `9e02bb812ad6305ba649fad2b1e0f3465f3a8bb1409a14eb3d9896649f03ab74`，与发布元数据一致。安装程序退出码为 0，安装后程序版本为 2.0.9.0；打包的 `desktop-cli.js --version` 返回 0.1.5-rc.1。

全局 DSH 与 Desktop 内置 DSH 分别核对。CiteCiter tarball 已通过干净 Web profile 安装和 Desktop 内置 CLI 安装。最终候选已安装到本机默认 home 的 Web、Desktop 两个 profile，安装退出码均为 0，两个 Client bundle 的 SHA-256 均与构建产物一致；升级前保存了原 profile 清单和锁文件。测试进程各自使用独立 home；未停止已有的日常 Web 进程。已运行的日常宿主需由用户重启加载新 Host 代码。alpha、next、TUI 和其他 Desktop 产品不在此次适配范围内。

## 旧数据升级

将 2.0.5 测试环境的来源会话、Topic、板书和学习卡复制到独立 home，用最新版宿主打开。Desktop 的只读恢复检查通过。另一个隔离进程继续运行旧 Observer 和 Exact Fork Topic，并成功调用来源读取工具；学习卡与迁移前一致。14 个原始 `session.jsonl` 文件的内容哈希在测试前后相同。

DSH 负责 Session v0 到 v3 的迁移。CiteCiter 不改写旧 `seedLength` 或事件记录。Exact Fork 的工具输入与标题投影使用恢复后的 `inheritedEventCount`，不按旧元数据中的序号截取迁移后的来源。历史引文保留文本；捕获时的序号不能保证仍对应当前来源事件。

Windows 自动化期间出现用户输入干扰、过期窗口和前台进程 ID 读取失败。恢复窗口定位后继续操作；工具异常不计为通过。原生保存窗口延迟被工具捕获，后续实际保存成功；没有将旧界面快照误判为导出故障。导出文件 SHA-256 为 `689fa598f999d9841ca2b2acd6432c98308ff5a0574c2168ba8d9a390f154bff`。

板书引用会保留当前学习阶段。用户在本轮明确选择保留该行为：引用填入问题框，发送时按选中阶段解释引用内容。此项作为确认后的产品逻辑保留，并写入中英文 README。

## Web 和其他限制

独立 Web 服务启动，真实 Host 和恢复结果通过。浏览器工具最初无法读取 request-header policy；恢复到可列出浏览器后，本地测试地址仍返回 `ERR_BLOCKED_BY_CLIENT`，没有完成新的 Web 交互验收。未绕过浏览器限制。

CI 配置覆盖 Ubuntu / Node 22.19.0 与 Windows / Node 24，使用同版 DSH 并分别测试源码和 tarball；运行结果以该 PR 的 CI 为准。未进行 Linux/macOS 原生界面测试。确定性模型验证接线、状态和持久性，不评价真实模型的教学质量、推导正确率或工具遵循率。本记录不承诺“无 bug”。
