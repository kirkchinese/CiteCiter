# DSH RC2 / Codex Connect 4.50–4.52 Web 联调

历史范围：2026-09-27–28，Web DSH 0.1.7-rc.2、CiteCiter 0.9.0-alpha.1。本文保留 Web 真实模型结果和通用工程结论；不同候选的证据仍归属原轮次，不构成当前版本验收。最终发布结果见 [发布检查](2026-09-28-release-gate.md)。

## 环境与边界

9 月 27 日 DSH next 为 0.1.7-rc.2；9 月 28 日 latest 也移到相同版本。Codex Connect 先使用未修改的 4.50，再更新至 4.52；4.50 的结果不自动计为 4.52 通过。主 Web 的 4.47 精确兼容例外已经撤销。通过进程命令行和端口检查保持只有一个进程写入主目录，保留真实会话与备份。

第十八轮更新 Connect 4.52：138 个安装文件与 npm 包逐字节一致，SHA-256 为 5cab311ed632fb2156188a13633d0bf5ca4c569dad8415da4c95ad4d5063e4a4。没有开启默认关闭的请求计量或任务编排。

## 通用修复

失效的继承模型保留为未发送草稿，提示用户选择有效模型；宿主接收选择后才保存模型设置并解锁发送。创建和选择轮盘动作均不自动调用模型。

主列表隔离的根因是 api-session-controller 通过 ctx.sessions.get(agent.id) === agent.session 判断是否广播成员。旧适配给 get 加入自有回退，使已加载 Topic 被当作主会话。修复保持 get/list 不变，仅转接确切自有对象的 flush；通过公共 llm/stream 等待自有 SessionStore 保存。没有添加主列表过滤器或修改 Agent Loop。

双击标题原先错误调用主 SessionStore，返回 session is not live in this store；标题服务改为挂在 Topic 自有 realm。模型菜单增加窗口内滚动、同步重新定位与子菜单焦点恢复，保存期间使用 aria-disabled 保留键盘焦点。

学习卡的示例改用明确 text/code 类型。工具参数、验证器共享契约；代码保留语言、缩进和换行，使用原生 CodeBlock 和安全 Markdown 围栏，旧字符串在读取时兼容为文字。错误记录不覆盖最后可用卡片。

独立 atomicReplace 仅对 Windows EPERM/EACCES/EBUSY 有限重试，不删除目标文件。真实 FileShare.None 占用在 250 ms 后释放时，336 ms 后替换成功；持续占用在 672 ms 后报原错误并保留数据；ENOENT 立即失败。该修复不能解释构建 UNKNOWN 的根因。

文档工具抽离为 document-tools.ts，返回 documentLength、requestedThroughOffset、hasMore 和 nextFromOffset；说明 UTF-16 偏移与合法边界，越界请求仍拒绝。搜索直接在原文进行不区分大小写的字面匹配，避免小写展开改变偏移。来源权限仍以用户已提交的附件为边界。

多窗口保留草稿曾报 ENOENT：本地 FileEntry.saved 被误当作永久有效，对方已移除持久字节。修复在用户明确保留时比较最新文件身份，对仍持有本地 File 的缺失附件重新分片保存，再执行修订检查；失败保留冲突，已释放控制器不接受迟到响应。

## 图像与附件

Connect 4.50 的真实生成返回 1536×1024 PNG；工具折叠时图片可见。第七轮按原 assetId 编辑生成图，以及按 attachmentId 编辑用户上传封面，均只调用一次并在实际灯箱检查目标和修改。更早上传图编辑的 120 秒超时保留为失败；超时后排队输入只消费一次，不把目标选择正确记作图片成功。

第十五轮 Web 在图片编辑执行期间归档 Topic，工具继续完成且归档状态不变；重新打开历史完整。蓝／橙／蓝三方块 PNG 为 1774×887、1010943 字节，SHA-256 为 7d0adae14ae4c48d9056d192aa3f09ab9d588f58158626dff00156ce2c1b8cef。

Connect 4.52 的第十八轮真实 read 读取 package.json，参数及原文可见；随后图像生成 14.054 秒，按同一资产编辑 56.577 秒。实际灯箱确认 A 蓝、B 由绿变紫、C 橙，箭头与方框分离；编辑期间排队输入在图像回合完成后只执行一次。

第十五轮真实 787076 字节 lib.webworker.d.ts 由 grep/read 读取，模型准确区分 Cache.match 与 CacheStorage.match；文件摘要为 d52ed68e7eb5881768a55713c9b5c7c443e6b46de15c04e348928b8efd20b110。第十七轮 Web 阅读器翻到第二页并真实选中文末，持久引用范围为 786816–786851；GPT-6-Sol 手动请求完成七次文档工具，解释接口合并与异步迭代。首答建议只写草稿，不自动发送。

第十六轮 Web 搜索返回 documentLength=8225；省略终点从 8096 读到文末，返回 hasMore=false、nextFromOffset=null。定界读取 7800–8099 返回 truncated=false、hasMore=true、nextFromOffset=8099，区分请求终点与文档终点。

## 构建、发布与限制

各轮按已记录候选执行 Host/Client 编译和打包；第十九轮运行时代码在第二十轮只更新 README，第二十二轮仅再改变发布元数据，最终 alpha.1 包摘要见发布记录。不要把文档等价性扩展为未测功能或平台已通过。

Windows 的 tsc 或 normalize-bundle 曾偶发 UNKNOWN，独立步骤及后续完整 prepack 通过；文件非只读、磁盘有空间，未找到稳定触发或占用者，没有增加无证据重试。新 Client 对 Host 构造器的值导入曾被 purity 检查阻止，移除后检查通过。

只读 PowerShell 的 CannotCreateTypeConstrainedLanguage 与中文编码问题由用户接受为上游限制，未降权限或隐藏 stderr。Edge 自动上传受扩展文件 URL 权限拦截，实际文件由用户选择；控制限制不能代替应用上传失败。清理旧开发目录的部分命令被自动审批拒绝，未改换工具绕过；用户随后手动清理，详见发布检查。

[Issue #9](https://github.com/kirkchinese/CiteCiter/issues/9) 的 RC2 版本闸门与 Typert 工厂问题通过实际 Web 产物检查：无兼容例外，七个具名 schema 和 Host/Remote 各三个 codec 工厂返回原 schema，27 个 peer 可解析并满足范围。五条相对运行时导入都有目标；第三方 JSDoc 的 ./types.js 不属于运行时缺失模块。

Linux/macOS 没有本轮实机验收。当前官方桌面与新 SDK 需要独立验收，不能使用本历史记录替代。
