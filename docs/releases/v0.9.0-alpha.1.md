# CiteCiter 0.9.0-alpha.1

[npm 预发布](https://www.npmjs.com/package/@kirkchinese/dsh-citeciter/v/0.9.0-alpha.1) 与 [GitHub Release](https://github.com/kirkchinese/CiteCiter/releases/tag/v0.9.0-alpha.1) 均已发布。next 指向本版，latest 保持 0.8.2；公开包与双端安装的验收包逐字节一致，见[发布检查](../validation/2026-09-28-release-gate.md)。

预发布版，npm 标签为 `next`，GitHub 标记为 prerelease。适配 Web DSH `0.1.7-rc.2` 和 Desktop `2.0.15` 内置的同版 DSH。正式版仍为 0.8.2；0.8.0 的 Linux 符号链接错误与弃用说明继续有效。本轮 Linux 暂不验收。

## 变更

- 修复 [Issue #9](https://github.com/kirkchinese/CiteCiter/issues/9) 的 RC2 安装与 Typert 激活失败：peer 范围明确包含 0.1.7-rc.2，七个具名 schema 和三个 strict codec 同时提供旧版 schema 与新版 create() 工厂。Host 与 Remote 共享同一契约，不需要 allow-version 例外。
- 图像和文件结果直接显示在工具卡下方，参数与原始输出仍可折叠；ToolMessage 独立于面板状态和宿主服务。
- 历史图片在宿主内预览，修复 Desktop 拦截 blob 新窗口后点击无反应的问题。新版复用 DSH 图片灯箱，旧版通过独立适配使用原生模态框；附件读取权限与 URL 生命周期保持不变。
- 提示词遵守明确的篇幅限制；图像编辑复用连接工具提供的附件或资产引用，不要求先复制到项目文件。
- 首答建议追问改为服从本次请求的可选默认值。用户禁止建议、只要结果或严格限定格式与篇幅时，要求省略整个追问块，避免末尾的默认规则覆盖前文约束。
- 学习卡示例明确区分文字与代码。文字使用 Markdown；代码保留语言、换行和缩进，使用 DSH 原生代码块与复制按钮，HTML/SVG 代码不自动变成预览。导出保留代码围栏，历史字符串示例继续按原 Markdown 读取，不改写旧日志。

- 迁移 DSH 0.1.7 的 Agent 注册、配置表单、Typert schema 工厂、会话状态、工具结果和 UI 图标接口。历史来源仍定位到原实体目录，日志格式迁移由 DSH 持久化层管理。
- 同一候选包通过独立适配层兼容 Desktop 旧接口。构建分别核对两套真实 SDK，不静态依赖旧宿主不存在的命名导出，不修改宿主 Agent Loop。
- 草稿文字、真实引用及附件字节持久化到所属 Topic。刷新和重启后通过原生附件接口恢复，不自动发送。修订号防止并发覆盖；确认接收后只清除对应提交，保留发送期间新增编辑。丢失响应需要用户核对或明确重试；损坏附件、保存冲突和未落盘编辑均有提示。
- 修复另一窗口移除附件后“保留本窗口草稿”因过期的已保存标记而报文件不存在的问题。明确保留时重新保存本地持有的缺失附件，再按最新修订提交；失败仍保留版本选择入口，不自动发送。
- 用户手动发送被宿主接受后，消息区定位到最新内容；模型继续输出时保留用户向上阅读的位置。延迟返回的发送结果不会滚动已切换到的另一个 Topic。
- 侧边与悬浮之间拖动时，图片重新加载和布局变化继续恢复阅读位置；布局产生的滚动事件不再覆盖用户的阅读状态。
- 修复发送与继续编辑之间的竞态：本次文字、引用和附件在发送事件中固定，保存期间新增的草稿不会被误发或清空。
- 修复切换 Topic 后被旧轮询结果切回的问题。导航期间暂停轮询，返回结果只更新仍被选中的 Topic。其他窗口的后台轮询不再改写上次使用的 Topic，避免刷新后恢复到旧导航。
- RC2 拒绝模型或思考强度设置时，不再提前保存被拒绝的配置；先由原生会话服务接受，再更新 Citer 元数据。
- 修复 RC2 在 Agent 启动时将 Citer 发布到主会话列表的问题。Host 的 get/list 保持原样，自有日志通过独立保存适配和公共模型流事件持久化，不移动来源日志。
- Topic 的标题服务与存储归属一致，修复双击重命名因调用主会话标题服务而失败的问题；复用当前宿主的标题实现和投影版本。
- 模型菜单按实际最大高度定位，长列表在菜单内部滚动，底部模型不再超出窗口。
- 切换模型或思考强度子菜单时，焦点保持在可用菜单项；保存期间模型按钮保留焦点但阻止重复打开。
- Topic 索引、草稿和文档元数据的原子替换对 Windows 短暂占用进行有限重试，累计等待不超过 620 毫秒。持续失败仍报告原始错误，不删除目标文件或放宽文件权限。
- 旧 Desktop 检测到新版日志格式时拒绝写入，保留原记录并提示在新版 Web 继续。
- 自由提问将真实选文追加到当前选中的未归档 Topic；没有选中或当前 Topic 已归档则新建。其他内置动作默认新建，自定义动作可设置目标。追加保留草稿、模型、权限和附件，不自动发送。
- 轮盘动作直接进入 Citer 输入框。删除重复的问题弹窗，以及附件菜单中无需实际选文的引用入口；加号直接选择图片或文件。
- 普通工具调用和 run_code 内的 PTC 子调用使用同一记录适配层，覆盖开始、结果、失败、附件和板书投影。后续同名工具成功不再隐藏早先失败。
- 学习路线默认关闭，当前提示词明确限制旧路线指令继续生效。开启时仍遵循用户指定的范围、篇幅、工具限制和卡片数量，不强制凑齐所有阶段。卡片功能保持可用，生成前继续要求模型核对结论。
- 同一 Topic 可引用多份文档，读取工具按已手动发送的文档地址选择目标。
- 文档读取与搜索拆为独立模块。搜索提供文档总长度；读取明确实际范围、剩余内容和续读位置，越界错误返回具体合法范围，避免模型猜测文末后重读全文。搜索在原文上匹配，避免 Unicode 大小写转换改变定位偏移。
- 适配 DSH 0.1.7 的可收缩详情轨道与主栏最小宽度；空间不足时新打开的原生详情优先，Citer 暂时收起并保留草稿，关闭详情后恢复。主动选文或点击 Citer 可进入独立页面，返回释放原界面。
- 板书截图独立于 Topic 面板，关闭面板后也能完成真实视觉检查；截图请求携带确切的 Topic 和板书版本，取消与超时由宿主管理。
- 归档 Topic 收到新的用户消息后自动恢复到活动列表，排队和插话均按宿主接收结果处理；工具结果、模型回答和旧消息出队不会恢复归档。
- 宿主模块解析支持 Desktop 的 `resources/app/` 与 `resources/app.asar/` 两种布局；CLI 继续先解析符号链接真实路径。
- 中英文 README 加入演示视频，并区分正式版基线与候选版。

## 兼容边界

主 Web 与 Desktop 2.0.15 均使用 DSH 0.1.7-rc.2、上游 dsh-codex-connect `0.1.0-alpha.4.52` 和同一 Citer 候选包。连接插件不再需要本地补丁或版本例外。4.52 的 Web 真实文件读取、严格 JSON 回答、图像生成、资产引用编辑和编辑后排队消费已完成；Desktop 已完成真实首答及 Web 历史、工具和图片预览恢复。4.50 的上传图片编辑、Desktop 后台生成等证据保留原版本归属，不自动算作 4.52 全部能力通过。图像能力需在 Web、Desktop 各自的 Codex Connect 设置中开启；view_image 与图片生成分别配置。请求计量保持默认关闭。

已知宿主问题：只读 PowerShell 的编码初始化与受限语言模式冲突，Desktop 的错误输出还可能乱码。原始错误在 Citer 可见；未通过隐藏错误或放宽权限规避。用户于 2026-09-28 确认将此项作为宿主限制，不阻挡本次 alpha 发布；这不代表该问题已修复。

RC2 新建 Topic 继承已下架模型时，保留未发送 Topic 和草稿，提示用户选择可用模型。宿主接受明确选择后才允许发送，没有自动更换模型。

## 验证

当前状态见[RC2 / 连接插件 4.50–4.52 联调](../validation/2026-09-27-connect-450.md)。发布范围为 npm next 与 GitHub prerelease，latest 保持 0.8.2。

包的 publishConfig 声明官方 registry 与 next；正式发布仍必须显式使用 --registry=https://registry.npmjs.org --tag next。本机 npm 从 tarball 发布的 dry-run 在省略 --tag 时仍选择 latest，因此不能只依赖包内 tag。显式参数的 dry-run 已确认目标为官方 npm、next、公有包，没有实际上传。Issue #9 的工厂与兼容闸门已用 Web、Desktop 实际安装的 RC2 校验器验证；这不代表独立的 PowerShell 缺陷已修复，也不替代其余功能验收。

见[alpha 验收记录](../validation/2026-09-23-alpha.md)、[RC1 补充验收](../validation/2026-09-24-rc.md)和 [RC2 双端验收](../validation/2026-09-24-rc2.md)。类型检查、构建和打包通过不代表用户流程已经验收。公开包、GitHub 资产和本地包的 SHA-256 均为 `15b722387edf919f86731c855420448bfe876118250b1e1e1ec6d6f2f066813f`。Windows 与 Ubuntu CI 通过；Ubuntu 静态检查不代表 Linux 实机功能验收。
