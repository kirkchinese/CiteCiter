# CiteCiter v0.4.2

这个版本修复了部分回答无法建立 Citer 的问题。

## 遇到了什么问题

在列表、嵌套列表、段落与列表相邻等回答中选中文字后，CiteCiter 可能提示：

> 选区无法映射到已提交的模型回答，请重新选择正文后重试

问题并不在用户的选择。浏览器会按页面结构生成选区文本，Markdown 则保留另一套换行和空白；两者在列表边界处不一致，导致 CiteCiter 无法把可见文字还原到原始回答。跨流程选择还可能把模型的思考内容带入匹配文本，而 Host 只接受已经提交的回答正文。

## 如何修复

- 区分 Markdown 原有空白与渲染器补入的结构分隔符，仅允许后者适配浏览器生成的换行和空白。
- 保持真实正文中的空白严格匹配，避免把 `foo bar` 错误映射到 `foobar`。
- 从跨流程选区中排除思考内容和翻译投影，只使用已经提交的模型回答正文。
- 增加列表、嵌套列表、思考内容与严格空白匹配的回归测试。

现有 Topic、Session 日志和设置格式均未改变，不需要迁移。

## 已测试

- 包内 74 项测试全部通过。
- 在真实 Chromium 页面中跨列表选取 462 个字符，能够还原到唯一的原始回答区间。
- Linux 上的 DSH Web `0.1.1-rc.2` 可用；Windows 与 macOS Desktop 留待对应系统继续适配。

## 安装或升级

```sh
dsh plugin --profile web add @kirkchinese/dsh-citeciter@0.4.2
dsh plugin --profile web list --depth 0
```

安装后重启 DSH Web 并刷新页面。正式 Desktop 适配仍暂缓，本版本不声明 Windows 或 macOS 安装包兼容性。

---

This release fixes selections that could not create a Citer from lists, nested lists, and other structurally complex answers. It reconciles browser-generated structural whitespace with Markdown source offsets, excludes reasoning and translation projections from committed answer text, and keeps real inline whitespace strict. Existing Topics, Session logs, and settings require no migration.
