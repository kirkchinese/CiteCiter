# CiteCiter v0.4.0

v0.4.0 moves CiteCiter to the current DSH prerelease line and refreshes its public positioning around source-bound, private, read-only learning Topics. It supports DSH `>=0.1.1-rc.1 <0.1.1-rc.3`; users remaining on DSH `0.1.0-rc.7` should continue using CiteCiter 0.3.2.

## Compatibility

- DSH Web `0.1.1-rc.2` is the primary supported host.
- The Linux source development shell of [dataelement DSH Desktop](https://github.com/dataelement/dsh-desktop), with its pinned DSH `0.1.1-rc.1` Web profile, is verified as a supported host. This is not a claim that packaged macOS or Windows installers were tested.
- Node.js `^22.19.0 || >=24.0.0` remains supported.
- The plugin remains a standard `dsh.client.platform: web` bundle and does not depend on Electron or Desktop-private services.

The Remote API, Topic metadata, private Session logs, settings fields, and read-only permissions are unchanged. Existing v0.3.2 Topics and settings require no migration or rewrite.

## Distribution and documentation

- The README now leads with the complete user outcome: ask about a committed DSH response without stopping the source Agent or changing the source Session.
- A compatibility table distinguishes current Web, the verified dataelement Desktop source shell, the v0.3.2 rc.7 line, and unsupported TUI clients.
- The package description and discovery keywords now identify private source-bound side threads, conversation branching, context management, and read-only learning.
- CI verifies the same source against DSH rc.1 on Node 24 and DSH rc.2 on Node 22.19 before packing the bundle.

## Install or upgrade

```sh
dsh plugin --profile web add @kirkchinese/dsh-citeciter@0.4.0
dsh plugin --profile web list --depth 0
```

Restart the corresponding DSH Web process after installation or upgrade.

## Post-release correction

The dataelement Desktop result above required its repository-internal `dsh-desktop-hmr-fallback` dependency to be made available in the isolated profile before CiteCiter loaded. It is conditional Linux source-shell evidence, not an out-of-box or packaged macOS/Windows Desktop claim. CiteCiter 0.4.1 targets the separate anywhere-labs DSH Desktop 2.0.2 release and keeps that target pending until both installer platforms are tested.

The v0.4.0 panel also depended on unsupported AppFrame grid writes. CiteCiter 0.4.1 preserves the side-by-side behavior through an owner-scoped, reversible, version-pinned compatibility adapter, removes its Host writes when the minimum widths do not fit or on disposal, and treats an AppFrame-owned public companion-panel contribution as the long-term fix.

A later real-provider audit also invalidated the original GO conclusion: follow-up control markup could leak into completed answers, a single oversized source event could stop pagination, retries lacked durable request identity, and the settings-document action had no recoverable status. These findings are corrected in v0.4.1; the original detailed report remains available in Git history rather than as main-branch test data.
