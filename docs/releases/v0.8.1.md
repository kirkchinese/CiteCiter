# CiteCiter 0.8.1

**0.8.0 已弃用，请升级到 0.8.1。** Linux 使用符号链接启动 DSH 时，0.8.0 可能无法创建或恢复 Topic，报找不到 `@deepseek-ai/dsh-agent-loop`。0.8.1 修复此问题，宿主基线保持 DSH 0.1.5-rc.1、Desktop 2.0.9。

**0.8.0 is deprecated. Upgrade to 0.8.1.** On Linux, a symlinked DSH launcher can make 0.8.0 fail to create or restore Topics with a missing `@deepseek-ai/dsh-agent-loop` error. Version 0.8.1 resolves the real CLI entry before loading host modules; Desktop keeps its ASAR module identity.

## 升级

Web：

```sh
dsh plugin --profile web add @kirkchinese/dsh-citeciter@0.8.1
```

Desktop：在应用管理终端执行：

```sh
dsh plugin add @kirkchinese/dsh-citeciter@0.8.1
```

安装后重启对应宿主。升级保留现有 Topic 与来源 Session，不需要删除数据或重新创建会话。同一 DSH home 不要同时运行 Web 和 Desktop 写入进程。

## 修复

0.8.0 从 process.argv[1] 建立宿主模块的解析位置。Linux/macOS 的 npm/pnpm 启动命令通常为符号链接；Node 保留 argv 中的链接路径，因此依赖查找从 bin 目录开始，打开或恢复 Topic 时可能报 Cannot find module '@deepseek-ai/dsh-agent-loop'。

CLI 分支现在先解析入口真实路径，再加载宿主的 AgentLoop、createScope 和 SessionStore。Desktop 继续使用 resources/app.asar/package.json，不对 ASAR 虚拟路径执行 realpath。无效入口直接报告原始错误，不静默回退到插件侧依赖。

不修改宿主 Agent Loop、Topic 存储、权限或会话内容。

## 验证

Ubuntu/WSL 的原生 Node 22.22.0 使用实际 DSH 0.1.5-rc.1 安装模块复现旧版失败。修复后真实入口、单层符号链接和多层符号链接均可加载三个模块，并与宿主模块保持同一实例。Windows Node 24.19.0 及 Desktop 2.0.9 内置 Electron 43.3.0 的 ASAR 模块身份检查均通过。

候选包已安装到本机主要 Web 和 Desktop profile。主要 Desktop 重启后恢复原有 Topic，真实模型手动发送和回复通过，来源会话文件未变。

类型检查与完整构建通过。Linux 检查针对启动模块解析，不等同于 Linux 全部界面和真实模型对话验收；本机 WSL 网络初始化失败，没有在其中启动另一个 DSH home 或模型服务。macOS 尚未实测。详细证据见 [验收记录](../validation/2026-09-14-symlink-launcher.md)。
