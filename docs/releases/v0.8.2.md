# CiteCiter 0.8.2

修复候选版，尚未发布。npm 正式版仍为 0.8.1；0.8.0 的 Linux 符号链接启动问题及弃用提示保持有效。

## 来源读取

`read_source_session` 新增 `sourceMaxSeq`、`hasMore`、`nextFromSeq` 和 `readScope`，分别表示可读快照上界、是否还有未扫描事件、续读起点和读取范围类型。保留旧字段，给全部输入输出字段补充语义说明。

`availableThroughSeq` 是兼容旧版的请求上界标记，不代表来源终点；它甚至可能低于本次 `fromSeq`。`capturedThroughSeq` 是扫描游标，包含被过滤的内部事件，不能按返回消息数量解释。`truncated` 只表示当前范围因字节预算停止；模型应使用 `hasMore` 与 `nextFromSeq` 判断续读。

新旧 Topic 均注入独立的来源读取说明。Observer 每次读取当前已提交事件；Exact Fork 的上界仅覆盖继承前缀。提示词区分未读、超大内容占位、权限拒绝和真实读取失败，避免把一个短窗口误判为全部来源。`observedThroughSeq` 保留字段名与存储格式，明确为上次扫描游标。

来源附件仍须由用户手动发送。草稿中删除的引用不会通过静态 Citation Context 重新注入；本次不恢复旧版只读系统提示词来覆盖原生权限。来源会话、归档及持久化格式不变。

## 建议追问

按用户确认，恢复原生 Topic 首答后的三条建议追问，并遵循现有设置开关。提示词规定语言、长度、去重及可解析格式；点击问题只填入草稿，用户手动发送后才调用模型。

来源工具声明与提示词分别放在 source-read-tool.ts、topic-prompts.ts，Topic runtime 负责提供已授权的来源快照和注册生命周期。

## 验证

类型检查与构建通过。使用真实主会话事件检查短窗口、续读、末尾、空范围、过滤事件、继承前缀、字节预算与超大内容占位。主要 Desktop 的真实模型已自行续读到末尾；首答追问显示、点击仅入草稿、后续回答不重复、关闭开关及来源附件移除均通过。详细结果和平台限制见 [验收记录](../validation/2026-09-14-source-read-guidance.md)。
