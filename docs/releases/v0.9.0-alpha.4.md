## 原生问答兼容

适配新版原生问题卡的 `dismiss()`、支持详情文本和已回答内容的只读查看。默认阻塞提问仍由用户回答或取消，不自动改为限时提问。

工具摘要按宿主结构化错误码区分用户主动取消、执行中断与普通失败；保留真实工具结果及日志，不从错误正文猜测取消状态。相同投影覆盖直接工具与 PTC 子调用。

新增独立 `tool-approval-projection.ts`，仅在工具调用、审批请求、拒绝决定和失败结果构成唯一且有序的明确关联时派生“已拒绝”摘要。缺少身份、重复或歧义事件、未知决定及成功结果均不推断拒绝；PTC 子调用按各自的调用 ID 关联。此变更只修正呈现，原始工具结果、权限决定和持久化日志均保留不变。双 SDK 类型检查、`pnpm build` 与 `git diff --check` 通过；`636409058e77` 安装重启后，官方窗口已显示真实历史 write 的“已拒绝”，展开保留原始参数和 `user rejected escalation` 错误。未经过审批的只读错误仍为普通失败，允许一次的成功结果保持成功，默认只读没有改变。此处通过的是呈现子项，不宣称所有权限组合都通过。

用户在 DSH 启用 timed 提问后，Citer 使用宿主公开等待接口接收剩余时长。输入区获得焦点时暂停尚未编辑的倒计时，失焦后恢复；首次编辑或选择“等我回答”后保持等待。收起卡片或切换 Topic 不销毁计时器；超时后仍可从原 Topic 补答。命名的工具问题支持显式跳过；跳过、超时和用户授权保持不同含义。

补答通过原生 `userQuestions.answer()` 写入该 Topic 的 Inbox 与日志；不会进入来源主会话。已归档 Topic 收到用户补答后恢复到活动列表。Citer 继续独立维护自己的会话目录，不把 Topic 显示在 DSH 主会话列表中，不改变只读默认权限和手动发送要求。

修复补答从未注入 `userQuestions` 的上下文调用服务而失败的问题，改由 Topic 自有作用域显式注入并随生命周期释放。安装后的真实模型已经接收历史问题的补答并按所选方式继续回答。补答日志曾被误归类为隐藏的上下文，现已呈现为用户消息，显示问题、所选项、自由文字或“已跳过”，不直接显示内部 JSON。工具行增加“已补答”派生摘要，保留原始超时结果及日志；自由回答保留原始缩进与首尾空白，仅用去空白结果判断是否跳过。

实际安装验收已确认历史选项与自填补答恢复为用户气泡。新的真实 12 秒多题迟答中，第一题选择 Python、第二题跳过，界面分别显示答案和“已跳过”，工具摘要同步为“已补答”，模型也正确复述了选择与跳过。包含空白保真修复的 `255f5aa1f764` 候选已安装，153 个文件与压缩包一致；官方桌面重启后历史呈现保持正确。双 SDK 类型检查与解析边界检查同时通过，但这些结果只覆盖已记录的检查项。

问答输入草稿在本次 Client 生命周期内保留，支持收起重开和切换 Topic；本轮没有增加独立问答草稿的跨重启持久化格式。普通消息草稿与已记录的宿主问答日志沿用各自已有的恢复机制。
