# CiteCiter v0.4.1 release candidate

The v0.4.1 source candidate fixes the blocking findings from the v0.4.0 post-release audit without changing CiteCiter's source-bound, private, read-only product limits or its existing Topic data format. It remains NO-GO until the real-provider, upgrade, Desktop, and performance acceptance gates complete.

## Fixes

- Follow-up control markup stays hidden during streaming, after completion, and after replay; only one valid terminal three-question block on the first answer creates shortcuts.
- Oversized source events become bounded type/sequence placeholders, so both Observer and Exact source reads can continue to later evidence.
- Creation and follow-up submissions use retry-stable Client identities, per-Topic single-flight state, durable Host deduplication, and late-response guards.
- The settings page uses the Host settings-document action and reports loading, missing, unsupported, success, and recoverable failure states.
- The learning panel keeps its `shell.overlay` registration but uses a version-pinned, reversible AppFrame grid compatibility adapter whenever the frame can fit a 360 px dock beside a 480 px conversation. The adapter falls back to an overlay only when that fit is unavailable, never calls `layout.closeDetails()`, and removes its frame attributes and CSS variables on close or unload.
- Host and Client teardown stop admission, abort cancellable work, and wait for accepted operations before their plugin fibers finish.
- DSH selection parsing uses the declared conversation dependency; Read Frog translation markers remain an isolated best-effort adapter.

## Compatibility

- The source candidate passes local unit, type, build, package, and deterministic Web fixture spot checks against DSH `0.1.1-rc.2`; these checks are not real-provider or packaged-Desktop evidence. The exact release tgz and candidate Git SHA are recorded separately when the candidate is frozen.
- The superseded overlay-only candidate passed the Node 22.19/rc.2 and Node 24.19/rc.1 package matrices. The replacement layout candidate must repeat those artifact checks; an rc.1 host must still keep a coherent lock or overrides because naive npm resolution may mix rc.2 transitive packages.
- [DSH Desktop 2.0.2](https://github.com/anywhere-labs/deepseek-harness-desktop/releases/tag/v2.0.2) at tag commit `9d18856ddea4f20eb3ef8c88b0436921c6b19606`, with bundled DSH commit `b150a551b8d465e31e418e1b2eaf5e79bbb7d28e` (`0.1.1-rc.2`), is the Desktop target. Its Windows x64 installer has SHA-256 `b31f63f8cf70d3fc07ed2ae36e5de7b1939e604bdb3be097de3383a82a06a787`; its macOS universal DMG has SHA-256 `35b40819b8ebfb0adfae232147ecb1f7199693fc331d049e436156aac7ccec45`. Installer acceptance is pending.
- The earlier dataelement Linux source-shell result remains historical, conditional v0.4.0 evidence and does not substitute for packaged Desktop acceptance.
- Node.js `^22.19.0 || >=24.0.0` remains supported.
- The implementation adds no Topic or settings migration; upgrade acceptance from v0.3.2 and v0.4.0 is still pending.

## Install or upgrade after publication

DSH Web:

```sh
dsh plugin --profile web add @kirkchinese/dsh-citeciter@0.4.1
dsh plugin --profile web list --depth 0
```

DSH Desktop tray terminal:

```sh
dsh plugin add @kirkchinese/dsh-citeciter@0.4.1
dsh plugin list --depth 0
```

An external DSH installation may use `--profile desktop`. Packaged Desktop includes Node.js, pnpm, and DSH. Restart the selected host after installation or upgrade.
