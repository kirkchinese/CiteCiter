# CiteCiter v0.4.1 release candidate

The v0.4.1 source candidate fixes the blocking findings from the v0.4.0 post-release audit without changing CiteCiter's source-bound, private, read-only product limits or its existing Topic data format. Its Linux/Web package and keyless browser gates pass. Real-provider acceptance and real-Topic responsiveness remain NO-GO items; packaged Desktop adaptation and acceptance are deferred and are not claimed by this release candidate.

## Fixes

- Follow-up control markup stays hidden during streaming, after completion, and after replay; only one valid terminal three-question block on the first answer creates shortcuts.
- Oversized source events become bounded type/sequence placeholders, so both Observer and Exact source reads can continue to later evidence.
- Creation and follow-up submissions use retry-stable Client identities, per-Topic single-flight state, durable Host deduplication, and late-response guards.
- The settings page uses the Host settings-document action and reports loading, missing, unsupported, success, and recoverable failure states.
- The learning panel keeps its `shell.overlay` registration but uses a version-pinned, reversible AppFrame grid compatibility adapter whenever the frame can fit a 360 px dock beside a 480 px conversation. It targets the details occupant relative to the public overlay instead of assuming a child index, preserving the conversation in Desktop Advanced mode. The adapter falls back to an overlay only when that fit is unavailable, never calls `layout.closeDetails()`, and removes its frame attributes and CSS variables on close or unload.
- Host and Client teardown stop admission, abort cancellable work, and wait for accepted operations before their plugin fibers finish.
- DSH selection parsing uses the declared conversation dependency; Read Frog translation markers remain an isolated best-effort adapter.
