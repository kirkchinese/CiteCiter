# CiteCiter 0.8.0

> **0.8.0 已弃用，请升级到 [0.8.1](https://github.com/kirkchinese/CiteCiter/releases/tag/v0.8.1)。** Linux 通过符号链接启动 DSH 时，0.8.0 可能无法创建或恢复 Topic，报找不到 `@deepseek-ai/dsh-agent-loop`。不要继续安装 0.8.0。

> **Deprecated: upgrade to [0.8.1](https://github.com/kirkchinese/CiteCiter/releases/tag/v0.8.1).** Version 0.8.0 can fail to open Topics on Linux when the DSH launcher is a symlink. The error names the missing `@deepseek-ai/dsh-agent-loop` module.

宿主基线：DSH 0.1.5-rc.1、DSH Desktop 2.0.9；可选 dsh-codex-connect 0.1.0-alpha.4.34。此版本替代 0.6.0，使用旧宿主的用户应继续安装 @kirkchinese/dsh-citeciter@0.6.0。

## 升级

Web：`dsh plugin --profile web add @kirkchinese/dsh-citeciter@0.8.1`。Desktop：在应用管理终端执行 `dsh plugin add @kirkchinese/dsh-citeciter@0.8.1`。安装后重启相应宿主；保留现有 Topic 与来源 Session。以下为 0.8.0 的历史变更说明。

## 行为变化

- 新 Topic 使用 DSH 原生 Session、标准 Agent preset、模型选择、权限、附件和发送队列。CiteCiter 不修改宿主 Agent Loop。旧记录迁移时逐条核验并保留原副本，权限不自动扩大。
- 新建 Topic、选文轮盘和引用板书只准备草稿。用户点击发送或按 Enter 后才启动回答；Shift + Enter 换行，输入法组词期间不提交。
- 来源对话地址、文档地址和引用文段以可删除附件显示。未发送的来源附件不会隐式进入模型上下文；相应读取工具在附件发送前拒绝读取。删除已发送引用的草稿副本不会撤回历史消息。
- 新 Topic 默认只读，不继承来源会话的更高权限。输入框中的模式选择使用 DSH 权限服务；用户可主动选择工作区修改、完全权限，或修改新 Topic 默认值。宿主审批和沙箱仍生效。
- 原生工具审批、补充问题与计划确认显示在对应 Topic，确认结果交回 DSH 的原生交互。
- 支持原生图片、文件附件、排队和插话。繁忙时 Enter 和发送按钮跟随 DSH 默认设置，Ctrl + Enter 临时切换；当前 Topic 的手动覆盖不改写宿主设置。等待状态来自 DSH 会话；附件上传和发送失败保留草稿。
- 区分宿主拒收与接收后的状态读取失败。后者不再保留已发送原稿，避免重试时重复提交；下一次正常读取清除临时错误。
- 附件被拒收时展示宿主错误。损坏或无效附件明确提示移除或更换，保留文字与附件供用户修改。
- 图文混合粘贴同时保留图片附件和说明文字，修复加入图片时阻止默认粘贴而丢失文字的问题。
- 文件拖入 Citer 面板时显示接收的 Topic。独立拖放模块隔离完整文件事件生命周期，修复同一次拖放被 Citer 与主对话重复接收；没有当前 Topic 时拒收，不转交主对话。文件选择与粘贴沿用同一附件入口。
- 可选学习路线由模型通过 `todo_write` 管理，按问题选择讲解方式和阶段。取消手动五阶段导航；主动回忆仍默认关闭，不安排间隔复习。

## 界面与板书

- 用户消息移除“你”标签，与原生对话一致保留内容气泡。已发送文件使用可点击的原生下载图标与文件名，支持键盘、读取状态和失败重试；下载按需读取当前 Topic 的原生附件，不启动模型。
- 附件读取统一支持图片与普通文件，按当前 Topic 的日志引用校验归属。图片使用原生图片读取，普通文件使用原生文件流读取与完整性校验，修复日志文件被图片接口拒收的问题；不通过文件扩展名推断类型。
- 恢复原生思考内容展示：保留只有思考的流式消息，支持单行预览与完整 Markdown 折叠展开；生成结束后保留当前展开状态。
- Citer 打开时将文档阅读入口收进右上角操作菜单，修复底部读书按钮覆盖模型选择的问题。
- 文档引用附件显示文件名，展开保留完整路径和快照地址；路径按纯文本显示，发送后仍可从日志重建附件。
- 修复后台刷新时附件菜单项重新挂载和键盘焦点回到第一项的问题；插话和排队统一使用“待处理消息”移除标签。
- 图标工具栏、可搜索 Topic 列表、双击标题重命名、模型 → 思考强度菜单。输入区按附件、权限模式、模型与思考强度、发送排列。
- 拖动标题栏脱离侧边；拖回窗口右缘停靠。窄窗口以独立页面占据主内容区，左上角返回后恢复来源。
- 小黑板统一在宿主对话标签中显示。公式引用渲染为数学内容，作为草稿附件保留。
- `blackboard_view` 返回浏览器实际渲染的 PNG，模型可在同一轮检查和修改布局。PNG 保存为 DSH 附件。支持 SVG、文本、公式和图片；沙箱 HTML iframe 暂不能截图。
- 板书截图排除被布局隐藏、透明或移出视口的画布。窄屏独立页面改用同一板书版本的离屏渲染，避免有尺寸但不可见的主区画布返回空白 PNG。
- 板书局部设置原生 Markdown 代码背景，修复浅色宿主主题下的浅字浅底；移除 SVG 强制提亮，保留图形原始颜色。绘图工具说明深绿画布、百分比坐标和截图范围，要求模型依据实际截图修正越界与重叠。
- 检测到宿主提供 `codex_connect_image_generate`、`view_image` 时，新 Topic 可直接使用；没有该插件时不注册替代实现。

## 兼容与限制

新 Topic 不再把完整来源历史隐式复制为 seed，而是保存来源关系并按已发送附件读取。这样移除来源附件会影响真正可见的上下文。旧日志通过公开持久化接口迁入来源实体目录，保留原头部与事件；无法核验时保留原位置并报告。

宿主未公开完整输入组件的跨会话嵌入接口；CiteCiter 使用薄 UI 适配公开的 ConversationController / SessionFace 方法。它不会自动继承所有宿主输入区扩展，例如任意插件的斜杠命令 UI。

Citer 在 `.dsh/sessions/<工作区>/<主Session>/citeciter/` 下独立管理 Topic、归档与删除。删除前释放该 Topic 的原生运行时，验证路径归属及符号链接，绝不删除来源 Session。七份已核验旧副本按用户确认移入 `migration-backups/`；主会话原文件保持不变。Citer 只在自己的列表显示。

视觉工具检查的是渲染图，并不保证知识正确。真实验收发现模型曾把错误结论写入学习卡，经追问和运行时验证后纠正。静态检查与流程成功均不能替代内容核查。详见 [真实模型验收](../validation/2026-09-12-native-real-model.md)。

## 工程变更

拆分原生会话工厂、实时成员、身份与持久化适配、来源读取、物理路径、日志迁移、安全删除、Topic 索引、板书截图、原生发送与队列、引用附件、文件附件、Topic 导航、标题编辑、模型菜单、权限选择及拖动模块。Host / Client 分别进行严格 TypeScript 编译。当前宿主检查点仍通过根 SessionStore 提交日志，因此 `citer-session-access.ts` 生命周期内适配其公开 `get` / `flush` 方法，将已登记的 Citer 身份路由到独立存储；不替换 `list`，不修改 Agent Loop，结束时恢复原方法。此处属于明确的宿主兼容适配，升级 DSH 后需单独回归。

修复运行中禁用插件时丢失最终中断记录的问题。自有 Session 工厂用 Cordis 有序 effect 先停止并排空 Agent，再撤下持久化服务和检查点适配；不修改宿主循环。网页启用或禁用插件后需刷新，更新客户端入口。

删除当前分支中的人工模型提供者、测试目录和临时验收脚本，保留 Git 历史。CI 只运行依赖锁校验、类型检查、构建和打包；功能验收使用真实模型与实际 UI，记录覆盖范围和未完成项。
