# CiteCiter 产品边界

本文记录 0.9.0-alpha.1 的现行产品规则。功能是否通过验收以[验收记录](validation/2026-09-27-connect-450.md)为准；代码或文档存在不等于已完成双端验证。[2026-08-23 调查方向论证](product-strategy-2026-08-23.zh.md)仅作历史资料，其中强制只读、Verify 优先及不提供学习卡片等旧约束已经被后续决定替代。

## 定位

CiteCiter 是 DeepSeek Harness 的来源关联工作区。用户从主对话、工具结果、原生文件预览或导入文档选取内容，在独立 Topic 中提问、理解代码、绘图或学习。主任务继续保留原有界面与日志，Citer 不自动向主 Session 注入消息。

学习理解是首要使用场景，同时支持普通问答、编程与图像任务。权限、模型调用、工具执行、排队、插话、停止和审批复用 DSH 原生能力。只有用户手动发送才启动模型；创建 Topic 或选择轮盘动作只准备草稿。

## 来源、草稿与会话

- 每个来源实体目录下的 `.dsh/sessions/<workspace>/<sourceSession>/citeciter/` 由 Citer 管理。Topic 的日志、草稿、归档和永久删除均限定在所属目录，保留主日志与迁移备份。Citer Topic 只出现在 Citer 列表。
- 来源地址、原文摘录、文档和板书作为真实、可移除的草稿引用。未发送草稿不进入模型日志，也不授予来源读取权限；已发送历史不因移除后续草稿副本而撤销。
- 自由提问追加到当前来源中选中的未归档 Topic；未选中或当前 Topic 已归档时新建。其他内置动作默认新建，自定义动作显式选择目标。已有草稿、模型与权限保持不变；加号只添加真实文件。
- 草稿文字、引用和附件字节持久化。宿主确认接收后仅清除该次提交，保留提交期间新增的编辑。重启不自动发送；响应丢失、保存冲突和附件恢复失败需要明确显示。
- 归档保留完整记录；从归档 Topic 手动发送并被宿主接受后恢复到活动列表。工具结果和模型回答本身不改变归档状态。自由提问不会向归档 Topic 追加，也不会因为引用选文而恢复它。

## 权限与模型

新 Topic 默认只读，即使来源具有完全权限。用户主动选择另一权限模式或更改新 Topic 默认值后，才允许对应操作；DSH 的审批、沙箱和工具限制继续生效。默认只读不等于永久禁止编程修改，也不等于禁用已配置的图像生成工具。

模型菜单先选择模型，再选择其支持的思考强度。继承的模型已经下架时，保留 Topic 与草稿并提示选择可用模型，不自动替换模型或发送。Codex Connect 图像能力在各宿主 Profile 中独立开启，工具未提供时明确说明不可用。

## 交互与学习

- 轮盘包含八个槽位。选择动作后直接进入 Citer 输入区，用户可调整文字、引用、模型和权限，再手动发送。
- 输入区依次提供附件、权限模式、模型与思考强度和发送。Enter 发送，Shift + Enter 换行；生成中跟随 DSH 的排队／插话默认值，Ctrl + Enter 临时切换。输入法组词期间不提交。
- Topic 使用列表导航，双击标题重命名。宽窗口保留主对话并排；窄窗口作为独立页面，返回后释放空间。拖动支持悬浮与停靠。空间不足时新打开的原生文件详情优先，草稿与阅读位置继续保留。
- 学习路线默认关闭。开启后，模型按问题选择底层逻辑、定性分析、定量板书、概念关联和总结卡片中的必要阶段，用原生待办维护进度，不要求用户逐阶段操作。
- 学习卡可单独请求。生成前要求模型在同一轮核对结论、计算和示例，纠正错误并标记未核实内容。示例区分文字和代码；主动回忆可选、默认关闭，不安排间隔复习。
- 板书只有一个功能入口。绘制后通过实际渲染截图检查效果；后台 Topic 不因切换界面或关闭面板而失去截图能力。视觉检查不能伪装成仅阅读绘图参数。

## 工程与验收

共享 Topic、来源、草稿和权限规则；版本差异由独立宿主适配层承担。React 接收状态和业务回调，组件不自行查找 Cordis 服务。除已记录的布局与自有会话保存适配外，不修改宿主 Agent Loop 或主会话服务的成员关系。

验收使用真实模型、真实来源分支和最终安装包，分别记录 Web 与 Desktop 的界面、持久化和副作用结果。静态检查不代替用户流程，模型答复完成不保证事实正确。当前只读 PowerShell 编码缺陷与剩余必测项仍阻止发布；Linux 本轮未验收。
